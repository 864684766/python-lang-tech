# Harness 学习路线

## 先分清这几个概念

Harness 是模型外部的运行与管理层：组织输入、请求模型、执行工具、记录结果、控制预算与权限。
模型生成文字或工具调用请求；本地 Python 函数由 Harness 执行。

`mini.py` 的 `Runner` 是本仓库的教学实现。工具循环课共用它，另有直接调用模型或普通 Python 的示例。每一课分别观察一个问题，
并不是每到一课才向 Runner 新增一个功能。加法和笔记只是演示用的工具。

- 模型返回本次 `AIMessage`，其中可能包含文字或零个、一个、多个工具调用。
- Harness 维护完整记录 `items`，并选取本次实际发送给模型的上下文。
- 无工具调用时，Runner 将回复视为终答，返回 `Turn`，其中含状态、`items` 和 `final_text`。
- `@tool`、`bind_tools`、`ToolMessage` 是 LangChain 的接法，其他 SDK 也可以实现相同机制。

## 怎么跑

在仓库根目录、安装了项目依赖的 Python 环境中运行：

```bash
python harness/hs_0_map.py
python harness/hs_1_cannot_act.py
```

先读 `hs_0` 的职责地图，再运行 `hs_1` 的首次工具调用。
`hs_0`、`hs_8`、`hs_15` 是概念课，不请求在线模型；其他课程包含在线演示，需要配置模型 Key。
`python harness/hs_11_verifier.py --offline` 只运行固定提案，无需 API Key。

初学者先读 [调试与答疑指南](./debugging_and_questions.md)：对照断点检查输入、返回和工具记录，形成具体问题后再问 AI，不只根据控制台的“成功”文字判断是否完成。

全部保留课程的入口：

```bash
python harness/hs_run_all.py
```

## 课表与每课的独立问题

文件保留原编号，按下表顺序学习；编号跳号是去重整理的结果，无需寻找缺失章节。

| 文件 | 本课要解决的问题 | 观察点 |
|------|------------------|--------|
| `hs_0_map.py` | Host、Harness、Model 分别负责什么？ | 只读职责和记录概念图 |
| `hs_1_cannot_act.py` | 答对是否代表执行过工具？工具调用怎样配对结果？ | 对比有无 add；辨认调用、结果、Turn 返回值 |
| `hs_2_tool_loop.py` | 后一步工具参数是否来自前一步的实际结果？ | add 在前，echo 在后，参数等于 add 返回值 |
| `hs_3_step_limit.py` | 工具请求持续出现时，代码怎样限制请求次数？ | max_steps 太小与足够时的状态 |
| `hs_4_approval.py` | 工具执行前怎样暂停、批准或拒绝？ | 批准前没有写入，批准后才执行 |
| `hs_5_context.py` | 完整历史与本次可见上下文怎样分开？ | 完整 items 保留，发送窗口变短 |
| `hs_7_when_not.py` | 什么时候直接用确定性程序即可？ | 固定步骤、明确命令与模型选择的区别 |
| `hs_8_vendors.py` | 不同应用形态怎样影响 Harness 架构？ | 概念比较；具体产品能力以其当前文档为准 |
| `da_0_create.py` | 如何用库替代手写循环，并辨认返回记录？ | Deep Agents 的 messages 与 mini 的 Item 对照 |
| `hs_9_handoff.py` | 内存会话结束后，新会话怎样恢复任务进度？ | 文件持久化，空历史重建输入 |
| `hs_10_playbook.py` | 怎样只改一条规则而保留其他规则？ | 追加、修订、去重与拒绝整篇替换 |
| `hs_11_verifier.py` | 怎样限定修改范围并挡住回归？ | 运费函数可改、测试不可改；固定提案与真实模型尝试分开 |
| `hs_12_lint.py` | 执行失败后，怎样提供可操作的反馈？ | 不产生违规副作用，错误结果说明替代工具 |

| `hs_14_two_axes.py` | 补丁格式合法是否代表任务效果改善？ | 同一模型使用旧、新手册；检查是否先读进度再正确写入 |
| `hs_15_ladder.py` | 可以改什么，前面哪里见过这些组件？ | 结合 hs_12、hs_13 等回顾；修改类别可重叠，不是严格等级 |

## 容易混淆的课程边界

- `hs_1` 讲执行与协议；`hs_2` 讲多步间的数据依赖。两者使用同一个循环，检查的问题不同。
- `hs_5` 选取已产生的交互记录；`hs_13` 决定外部资料何时加载；`hs_9` 负责跨会话恢复进度。
- `hs_9` 保存任务状态；`hs_10` 合并规则修改。只修改指定条目的通用演示集中在 `hs_10`。
- `hs_4` 控制工具是否可以执行；`hs_11` 判断修改提案能否合并；`hs_12` 研究失败反馈怎么帮助恢复。
- `hs_10` 处理补丁如何合并；`hs_11` 做修改范围和回归检查；`hs_14` 区分补丁格式与实际效果。
- `hs_0` 建立分层地图；`hs_8` 比较架构；`hs_15` 索引优化对象。三课不再重复在线加法或验收演示。

## 学习与实现的范围

先完成基础执行课与 Deep Agents 接入，再学 `hs_9` 到 `hs_14` 的持久化与改进机制，
最后读 `hs_15`，把前面的具体组件与可修改对象联系起来。

`mini.py` 用条数切窗口，是教学简化；实际系统还需要按 token 预算管理输入，
并保证工具调用与结果不会被切成不完整的消息序列。完整历史保存在内存中不等于持久化。

各课的实现范围不同：`hs_11` 使用受限语法执行候选函数和固定测试；`hs_12` 打印两种反馈，但只真实运行指导性反馈一组；
`hs_13` 使用字典模拟文档，比较字符串长度，并按指定路径读取，不是自主选择 Skill 的完整实验。
`hs_14` 根据真实工具记录评分，但进度是固定文本、笔记只在内存中，两个任务的一次结果也不能证明所有场景有效。
示例不构成通用安全沙箱；生产评估还需要实际任务、回归集和更充分的重复验证。
本仓库不实现论文中的候选搜索、整库进化或权重训练。
